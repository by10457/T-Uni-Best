# 编码行为准则（Karpathy Guidelines）

减少常见 LLM 编码错误的行为指南，来源于 Andrej Karpathy 对 LLM 编码陷阱的观察。

> **权衡说明**：这些指南偏向谨慎而非速度。对于琐碎任务，灵活使用判断力。

---

## 1. 编码前先思考

**不要假设。不要隐藏困惑。暴露权衡。**

开始实现前：

- 先检查仓库事实，再明确会影响实现的假设。
- 存在多种解读时，说明选择及依据；只有不同选择会显著改变结果或风险时才暂停询问。
- 如果有更简单且满足需求的方案，直接说明取舍。
- 不把可通过代码、配置、历史实现或只读命令确认的问题抛回给用户。

---

## 2. 简洁优先

**最少的代码解决问题。不做推测性扩展。**

- 不添加未被要求的功能。
- 不为单次使用的代码做抽象。
- 不添加未被请求的"灵活性"或"可配置性"。
- 不为不可能发生的场景添加错误处理。
- 如果你写了 200 行但 50 行就够，重写它。

**自检问题**：「一位资深工程师会说这过于复杂吗？」如果是，就简化。

---

## 3. 外科式修改

**只改动必须改动的。只清理你自己制造的混乱。**

编辑现有代码时：
- 不要"顺手改进"相邻代码、注释或格式。
- 不要重构没有坏掉的东西。
- 匹配现有风格，即使你会用不同的方式写。
- 如果你发现不相关的死代码，提及它——不要删除它。

当你的改动产生孤儿：
- 删除**你的改动**导致的无用 import/变量/函数。
- 不删除已有的死代码（除非被要求）。

**检验标准**：每一行被修改的代码都应该能直接追溯到用户的请求。

---

## 4. 目标驱动执行

**定义成功标准。循环直到验证通过。**

将任务转化为可验证的目标：
- "添加验证" → "为无效输入编写测试，然后让测试通过"
- "修复这个 bug" → "编写复现测试，然后让测试通过"
- "重构 X" → "确保重构前后测试都通过"

多步任务，先陈述简短计划：
```
1. [步骤] → 验证：[检查项]
2. [步骤] → 验证：[检查项]
3. [步骤] → 验证：[检查项]
```

强成功标准让你可以独立循环完成任务。弱标准（"让它工作"）需要反复确认。

---

## 5. 注释服务于维护

**写清原因和约束，不机械翻译代码。**

- 新增或修改的业务规则、异常降级、兼容路径和跨端差异使用简洁中文注释。
- 对外 props、事件、公共类型、store action、composable 和不直观的函数使用中文 JSDoc。
- 自解释的局部变量、简单 getter/setter、明显的模板结构不需要逐项注释。
- 改变行为时同步修改相邻注释；发现与实现矛盾的旧注释且属于本次范围时一并修正。
- 不用大段注释掩盖复杂实现；能通过清晰命名和拆分表达时优先改进代码结构。

### 页面业务代码的最低覆盖范围

“文件内私有”不等于“无需注释”。新建页面或在页面中落地完整业务时，以下声明必须逐项使用简洁中文 JSDoc：

- 手写业务类型：说明业务对象；字段存在单位、取值范围、默认值或特殊语义时补充字段说明。
- `<script setup>` 模块作用域的每个手写变量，包括 store、常量、响应式状态、计算属性、加载/提交标记、任务标识和定时器。
- 页面内业务函数、事件处理函数和异步流程函数；参数或返回值不直观时补充 `@param`、`@returns`。
- 生命周期中包含业务恢复、资源释放或跨端行为时，在注册语句前说明触发的业务动作。

禁止用一条注释覆盖连续多个变量，也不能用“页面状态”等分区标题替代逐变量职责说明。import、框架宏显然配置、函数内临时变量和回调形参不要求机械补注释。

```ts
/** 当前业务订单 ID，使用字符串避免长整型精度丢失。 */
const orderId = ref('')

/** 校验提交参数是否满足后端约束。 */
function validateForm() {}
```

### 交付前注释审计

1. 检查本次新增或修改的业务类型、模块作用域变量、计算属性和函数。
2. 从文件顶部向下确认页面模块作用域声明均有仅属于自身的中文 JSDoc。
3. 确认注释说明职责、原因或约束，而不是复述变量名。
4. 确认行为变化后没有遗留过时注释。

## 在本项目中的应用

| 场景 | 应用准则 |
|------|---------|
| 创建新页面 | 用 `uni-page-generator` skill；只实现当前需求的页面结构 |
| 修改 API 接口 | 只改 `src/api/` 对应文件；不顺带重构 HTTP 层 |
| 样式调整 | 同时加载 `css-styling`；优先原子化类名，不重写整个组件样式 |
| TypeScript 报错 | 修复报错本身；不重构周边类型定义 |
| 性能优化 | 先确认问题存在；不做未经验证的推测性优化 |
